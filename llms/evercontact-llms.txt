# Evercontact

> AI-powered contact intelligence that automatically extracts, enriches, and syncs
> contact data from email signatures across Google Workspace and Microsoft 365. A
> multilingual model parses names, titles, phones, and addresses from the signature
> block of every email (30+ languages), deduplicates and enriches person records,
> and syndicates clean contacts to CRMs, address books, and data warehouses.
> Operated by One More Company Inc. (New York, NY). Evercontact publishes no
> llms.txt of its own (probed 2026-08-14, HTTP 404 on every host), so this file is
> generated by the API Evangelist enrichment pipeline from the public site and the
> artifacts in this repo.

## API status — read this first
- A REST API is documented (parse, enrich, contacts, webhooks, events) at https://www.evercontact.com/api.html.
- No OpenAPI, Swagger, GraphQL, AsyncAPI or JSON Schema document is published anywhere. Probed the docs host, the apex, app.evercontact.com and the API host root on 2026-08-14.
- API access is not self-serve. The API page ends in a "Get API access" form; keys, the full reference, and the sandbox are issued through a sales conversation.
- The published base URL https://api.evercontact.com does not currently serve Evercontact: DNS points at an AWS load balancer presenting a certificate for b2b-lb.eu-prod.sonysnacloud.net, TLS fails, and the host returns 403. Do not attempt to call it.
- No MCP server, no A2A agent card, no /.well-known/ documents, no security.txt.
- SDKs for Node, Python and Go are advertised on the API page but exist in no public package registry.

## API (as documented)
- [Evercontact API](https://www.evercontact.com/api.html): REST — parse, enrich, contacts, webhooks, events. Documented base URL https://api.evercontact.com, versioned /v1, Bearer-token auth (ec_live_ prefix).

## Operations (as documented)
- POST /v1/parse: Extract a structured contact from a signature block. Returns name, title, company, email, phone, confidence.
- POST /v1/enrich: Complete a known contact with title, company, and verified detail.
- GET /v1/contacts/:id: Retrieve the canonical, deduplicated person record.
- POST /v1/webhooks: Register an endpoint to receive relationship events.
- GET /v1/events: Paginated stream of contact and company changes (contact.created, contact.updated, company.linked).
